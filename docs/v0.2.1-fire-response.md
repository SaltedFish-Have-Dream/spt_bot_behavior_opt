# 0.2.1 重新露头与无掩体自卫

上局海岸线日志中，Bot 已经确认个人视觉却不一定随即开枪：`t=340.37` Bot 3 看见玩家，`t=341.13` 才有原生接受新连射；期间还有原生瞄准和模组反应门槛。另有数次 `REPEEK_RECOGNIZED` 和可见时的避险状态。本次改动处理两种有来源的等待，不改变初次发现、枪线遮挡或原生瞄准规则。旧日志无法证明用户描述的每次未开枪都由同一原因造成，新版会留下更明确的边沿日志。

## 行为边界

- **同位置重新露头：** Bot 必须在失视前已经完成模组反应准备；目标身份不变，失视后八秒内在上次目击点六米内再次由个人视觉确认。此时不重复等待模组的等级反应与准备计时。只是短暂看见、尚未完成准备的 Bot 仍采用原有的八成等级等待。首次接敌完全遵守等级曲线。
- **射击安全不变：** 再露头仍需当前武器就绪、原生瞄准器 `IsReady`、原生可射击部位、武器冷却、两次预算内物理验证和原生 `Shoot` 接受。失视时反应门立即清空，不能对旧位置盲射。更快的是已经认识该枪线的 Bot 省掉重复的模组时间，而不是无视游戏射击条件。
- **危险中的无掩体自卫：** Bot 仍先查询已验证掩体并尝试合法卧姿或有限短距撤离。仅在确认掩体不可用、当前无路线移动或查询排队、已卧倒或不能合法卧倒、个人真实目视玩家、武器有弹且就绪、没有治疗/换弹、压力未达最高档，并在玩家枪弹威胁后至少 0.75 秒时，才允许瞄准和射击验证。新掩体、新危险、高压、恢复动作或撤离移动会立即关闭窗口。

两个功能默认开启，可分别用 `Tactics.FastRepeekFire=false` 与 `Tactics.ExposedSelfDefense=false` 关闭后重启游戏做 A/B 对照。`Tactics.SuppressionResponse=false` 时无掩体自卫也关闭。Boss、护卫、Raider 和 Bot 对 Bot 的原生射击不进入这些规则。

## 日志验证

安装时同时替换 `AiBehavior.Client.dll` 与 `AiBehavior.Core.dll`，重启后确认 `START version=0.2.1`、`FIRE_RESPONSE_RULES fastRepeek=True exposedSelfDefense=True`、`READY` 目标数相符。

建议在相同 Bot、掩体口和武器下分别观察首次露头与再次露头。日志链路为 `SIGHT_CHANGED visible=True` → `REPEEK_RECOGNIZED readyAtLoss=True`（仅再次露头）→ `FIRE_OPPORTUNITY_WAIT` 或 `FIRE_OPPORTUNITY_READY visibleMs=...` → `SHOT_BLOCKED` / `SHOT_NATIVE_RESULT`。若 Bot 已经瞄准但仍不开枪，`FIRE_OPPORTUNITY_WAIT reason=Reaction` 表示模组计时未完成；`NativeAim` 表示原生瞄准尚未就绪；`NoShootablePart` / `VisionStale` 表示视觉或可射击部位不满足条件；`Recovery` / `Evasion` 表示恢复动作或避险动作仍优先。`FIRE_OPPORTUNITY_READY` 不等于已经开枪，后面仍须查射击队列、枪线和原生结果。关键明细限频，最终 `COUNTERS` 记录事件总数。

无掩体危险场景应先看到掩体查询失败、卧姿或撤离处理，再出现 `EXPOSED_DEFENSE_READY`；若出现 `SHOT_NATIVE_RESULT` 才说明实际发起了合法新连射。连续玩家近弹保持最高压力时不应出现新自卫窗口。记录 Bot 位置、玩家是否再次从同一掩体口露头、间距，以及玩家目视感受到的开火延迟，才能把行为体验与 Bot 匿名编号对齐。

**性能影响：低，静态分析预估，未做新版局内实测。** 再露头只增加每 Bot 两个布尔状态；等待明细只在可见窗口中原因变化时计数，输出继续受全局日志限额限制。无掩体自卫沿用既有射击队列、每秒 120 个射线令牌和单帧射线额度，不新增导航、碰撞体扫描或常驻对象搜索。若许多 Bot 同时目视玩家且满足自卫条件，原生瞄准、射击验证及动画调用可能集中在同一帧；应查看新版 `TIMING`、完整帧时间和 GC，不从上局均值推断收益。
