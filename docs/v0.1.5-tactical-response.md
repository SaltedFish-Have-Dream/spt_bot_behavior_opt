# 0.1.5 轻量战术反馈

日期：2026-09-23。目标版本：SPT 4.1.5、EFT 0.16.9.5-40743、BigBrain 1.5.0。

本版先落地四项能与现有行为衔接的设计：失效掩体记忆、个人受压反馈、接近线索时有限停看、有效掩体移动保持。SAIN 仅作为行为设计参考，新增逻辑由本项目自主实现，没有复制 SAIN 源码，也不加载 SAIN 程序集。沿用已有 BigBrain 层，不新增前置或额外行为层。

## 选择与实现

参考基线为本地 SAIN v4.5.1，提交 `2d1d9257dbb3af535e9189e6181311f6355aec27`。具体源码依据见仓库中的 `docs/sain-behavior-reference-4.5.1.md`；该分析以本项目 0.1.4 为基线，表中的“待实现”描述保留为当时状态。

| 借鉴的行为思路 | 本版自主实现 | 控制成本的方法 |
| --- | --- | --- |
| 掩体遭受攻击后应重新评估 | 在已到达的自有掩体处被玩家直接命中，暂时排除该点并尝试换位 | 每个 Bot 固定四项记录，查询时最多四次平方距离比较，不持续扫描环境 |
| 连续近弹应影响战斗意愿 | 压力累积与衰减，高压优先隐蔽，回落后可在掩体内有条件还击 | 单个标量、固定时间窗口合并事件，复用已有命中和近弹入口 |
| 接近疑似接触区域应有搜索节奏 | 沿验证路线接近线索时短暂停看，然后继续推进 | 复用剩余路线长度，不另做转角射线或寻路；每区域最多两次 |
| 动作应有完成条件和中断条件 | 普通视线波动不打断有效掩体移动，紧急情况和控制交接仍优先 | 复用状态机与路径，只增加值判断，避免不必要的停止与重发 |

本版没有加入自动侧倾、复杂拐角探头、盲射压制、完整性格系统或小队包抄。搜索停看是接近线索时的有限等待，不代表识别出了具体危险转角。低开销是实现目标，尚未通过同场景实测证明比 SAIN 更快。

## 行为规则

### 失效掩体记忆

只有 Bot 正由本插件控制、已经到达有效掩体，并且被本机玩家直接命中，才记录失效位置。移动途中受击、近弹、普通枪声和同组告警不能证明该掩体本身失效。

记录保存十二秒，排除位置周围两米的三维邻域。相近位置合并，最多四项，容量满时替换最早到期项。读取、控制交接和同区域枪声不会延长封锁。原生候选收集、导航投影前后和结果接收都核对失效记录，防止投影重新落回同一点。

失效时撤销该点和旧路线，使用原有共享查询预算尝试附近替代掩体；候选确实失败后仍走现有合法趴伏回退。记录只属于当前 Bot，不全队广播，也不会因一次受击提高全局寻路额度。

### 受压反馈与掩体内还击

个人命中权重为 2.5，近弹权重为 0.9；同一个 0.25 秒窗口只累计最强事件，近弹后命中只补差值并确保首次有效命中进入高压。重复命中回调不会持续抬高同一窗口的压力。上限为 4，每秒衰减 0.8，按经过时间计算，帧率不会改变基本恢复速度。同组受击通知只保留原有避险告警，不累积个人压力。

压力达到 2.5 进入 `Pinned`，降至 1 或以下才退出，避免阈值附近反复切换。当前避险动作在高压、无有效掩体、缺少真实视线或正在恢复时优先隐蔽。只有已到达有效掩体、停止移动、压力回落、距最后危险至少 0.75 秒且目标真实可见时，才尝试还击。原生武器与瞄准检查、等级反应门槛、友军和遮挡验证全部保留。

还击不等于探头：本版不会为了制造射击机会增加侧倾或新姿态写入；掩体完全遮挡目标时继续隐蔽。新增门控只作用于本插件实际取得控制的玩家避险动作，原生高优先级层与 AI 互战不受该门控控制。

原有五秒避险规则保持：真实命中、近弹和有效同组告警更新原有危险时刻，普通枪声不刷新。压力本身不延长危险和调查寿命；安静五秒后仍按生命、弹药和恢复条件评估有限推进。关闭 `SuppressionResponse` 后恢复旧版避险期停火方式。

### 接近线索时的有限停看

只在准备执行下一段有效缓存路线、尚未看到玩家、没有正在发生的危险或恢复需求时安排停看。剩余折线路程必须大于 1.2 米且不超过 18 米，线索至少剩余两秒；路线过期或偏离时直接回到原导航流程。

默认 PMC 停看时长由现有线性战术倾向计算：`0.45 + 0.35 × (1 - 战术倾向)` 秒。1 级约 0.70 秒、60 级约 0.50 秒，中间等级线性变化。普通 Scav 使用固定模板；狙击 Scav 不执行移动搜索。

同一区域最多两次，两次开始至少相隔六秒，并且 Bot 实际前进至少六米。相同身份、区域中心偏移不超过四米时不重置次数；控制交还和再次接管也不退还次数。危险、状态变化或原生抢占立即取消当前等待。等待不消费下一段路线，不延长路线的八秒缓存期或线索寿命；结束后继续原有搜索与失败回退。

### 掩体移动保持

只有正在执行本插件路线、目的地仍是同一个有效掩体、尚未到达且具备移动资格时，才适用保持。普通可见性变化和新的战术抽样不会让 Bot 无故放弃这段路线；`Cover / Disengage / Evade` 之间可以保留同一段有效移动。

实际医疗或换弹已开始、线索消失、掩体失效、路径卡住、失去移动资格或 BigBrain 交还控制，仍会按原规则停止或重新规划。新的玩家危险优先切换为避险；若当前路线仍通向有效掩体，可以继续利用它。该机制不提高层优先级，不覆盖原生手雷规避或故障处理。

## 范围与开关

全部增量只使用本机真人玩家的有效事件和交战情境。AI 枪声、AI 弹道和 AI 互战不新增压力或掩体失效记录。已有玩家线索仍有效时可能继续搜索，不能仅凭 Bot 仍在移动认定混入了 AI 来源。

PMC 延续 1～60 级线性能力；新增等级差异仅体现在停看时长，压力权重、掩体封锁时间和查询预算不随等级增加。普通 Scav 固定模板，狙击 Scav 不移动追击；Boss、护卫、Raider 和其他非白名单角色继续保留原生行为。

配置文件：`BepInEx/config/local.aibehavior.opt.cfg`。以下四项默认均为 `true`，更改后重启游戏，可逐项对照测试。

| 配置项 | 关闭后的行为 |
| --- | --- |
| `Tactics.CoverFailureMemory` | 不记录或过滤短期失效掩体 |
| `Tactics.SuppressionResponse` | 不累积新增压力，避险期保留旧版停火方式 |
| `Tactics.SearchObservation` | 沿现有验证路线直接推进，不新增停看窗口 |
| `Tactics.CoverCommitment` | 按原状态切换处理掩体移动，不启用新增保持判断 |

## 日志与验收

启动应出现 `START version=0.1.5`、`PLAYER_RULES mode=local-human-only` 和 `TACTICAL_RULES`。后者记录实际四项开关、失效记忆容量与寿命、压力合并窗口和停看上限。补丁数量仍为基础 11 项，AI Limit 1.9.2 适配成功时为 12 项。

| 新增证据 | 用途与边界 |
| --- | --- |
| `PRESSURE_CHANGED` | 压力档位跨过阈值，含前后档位和当前值；明细受限频，不保证每次变化都写出 |
| `COVER_INVALIDATED` | 到达掩体后遭玩家直接命中，已撤销失效点；后续是否找到替代点看查询和移动日志 |
| `SEARCH_PAUSED` | 开始一次有限停看，含计划时长、剩余路线长度和本区域次数；不等于导航失败 |
| `COVER_MOVE_KEPT` | 掩体族状态切换时实际保留移动；不证明最终到达，也不会为维持同一状态逐帧记录 |
| `COUNTERS.CoverCandidateRejected` | 候选被短期失效记录过滤的次数，包括之后其他候选成功的请求；不是唯一掩体数 |
| `COUNTERS.ShotPressureBlocked` | 本插件避险期间因尚不满足掩体还击条件拒绝的新射击或排队请求次数；也包含功能关闭后的旧版停火规则 |

普通明细继续共用全局日志令牌和单 Bot 两秒间隔；累计计数保留被限频的事件。判断还击应结合 `PRESSURE_CHANGED`、实际 `Evade` 动作、当前可见性及既有 `SHOT_NATIVE_RESULT`，不能把“许可通过”当作命中。

优先复测以下场景：

1. 海岸线 30～120 米枪声调查：只打偏，观察接近、短暂停看后继续推进及到达/失败退出。停看不应无限续期，重复近处枪声不应反复重建路线。
2. Bot 在掩体处遭直接命中：检查 `COVER_INVALIDATED`、替代掩体或合法趴伏，十二秒内不应重复接受同一失效点；只打近弹或通知同组成员时不应误封锁。
3. 持续近弹后停火：检查压力升降、高压隐蔽、有有效视线时的条件还击，以及最后危险五秒后的恢复/推进；不能变成永久蹲伏或无视遮挡开枪。
4. 掩体移动中短暂丢失视线：应继续到有效掩体。再测试医疗、手雷规避、失效路线和原生层交接，确认保持机制不会阻止紧急退出。
5. 切换目标为其他 AI、远距离停用与再次激活、连续两局退出：确认没有 AI 来源压力、旧查询或永久停看；`RAID_END` 应为 `remainingBots=0 pending=0`。
6. 四个开关逐项关闭，比较行为和 `TIMING`、查询计数、外部帧时间与 GC；先固定地图与 Bot 负载，避免把静止或未接管当作性能收益。

## 验证证据与性能

本机 Release 客户端与独立检查工程构建通过，零警告、零错误；通过 **62 组场景、61,570 条断言**，核对 **24 项 API 签名和六个角色常量**。新增检查涵盖压力事件合并、连续射击与安静恢复、时间步长和高压退出缓冲、来源过滤、失效点容量与过期、停看次数和中断、路线消费与到期、掩体移动保持和紧急退出、还击条件及五秒危险边界。

预热后的独立 .NET 10 测试对新增纯逻辑热循环运行一万次，没有观察到托管分配。该结果仅覆盖被测值逻辑，不代表游戏 Mono、客户端、原生方法、路径数组和日志整体零 GC。尚未进行 0.1.5 局内实测或原生/本插件/SAIN 三组对照。

新增代码的游戏性能影响评级：**低（五档中的低档，静态预估）**。Bot 初始化时增加固定容量小对象和数组；压力更新为常数时间，失效记忆每次最多检查四项，停看读取已有路线长度，保持移动只是状态条件。不新增独立物理扫描、协程、Harmony 入口或全地图 Bot 搜索。

沿用全局额度：射线每秒补充 120、单帧最多八次；寻路 12、单帧一次；导航采样 36、单帧三次；局部扫描 6、单帧一次。实际请求量仍会随玩家事件和受管 Bot 数变化，额度不变不代表耗时不增加。

多个 Bot 同时在失效掩体处受击会集中请求替代路线；恢复还击会竞争既有射线队列；复杂地形的单次同步 NavMesh 调用、原生动作和日志监听器阻塞仍可能形成瓶颈。0.5 毫秒是可推迟工作的软预算，不能中断已开始的同步调用，也不是最坏帧保证。旧版海岸线数据不能当作本版性能结果。

执行 `tools/Build.ps1 -Package` 生成 `dist/AiBehaviorOpt-0.1.5.zip`。包内只有两个自有 DLL 和六份说明，不包含游戏、SAIN、BigBrain 程序集或参考源码。构建不会写入游戏目录。关闭游戏后同时替换两个自有 DLL，重启并核对版本和 `TACTICAL_RULES`。

| 源码位置 | 本版职责 |
