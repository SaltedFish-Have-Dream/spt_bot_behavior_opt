# 0.3.0 玩家交战战术适配

参考源码固定为 `reference/SAIN` 的 SAIN 4.5.1 提交 `2d1d9257dbb3af535e9189e6181311f6355aec27`。本版是独立实现，不复制 SAIN 类或在运行时加载 SAIN。目标游戏为 SPT 4.1.5 / EFT 40743 / BigBrain 1.5.0 / Waypoints 1.9.0。行为增强仅针对本机真人玩家；普通 Scav 使用固定模板，PMC 的短距突击机会随既有等级战术概率线性增加，Boss 和其他特殊角色保持原生。

| SAIN 战斗能力 | 本模组对应行为 | 证据与边界 |
| --- | --- | --- |
| 站立射击、远距射击、贴脸缠斗 | 真实目视时原生瞄准、枪线验证、近距后撤、6～25 米侧移、距离射击模式和新增 ADS 迟滞 | `FIRE_OPPORTUNITY_READY`、`AIM_MODE_CHANGED`；不改原生散布和后坐力 |
| 掩体战、受压、撤离、治疗 | 局部遮挡与完整路径验证、五秒危险、失效掩体、合法趴伏、原生治疗/换弹；新增失视后一次换掩体 | `COVER_SHIFT_REQUESTED`、`QUERY_SUCCEEDED`、`COVER_SHIFT_ARRIVED`；掩体失败会回退旧点 |
| 听声停看、搜寻、短距突击 | 玩家脚步 18 米内短暂停看；视觉失去 1.25 秒后，具备资格的 PMC 向 6～22 米同层最后目击点有限推进 | `AMBUSH_SELECTED`、`RUSH_SELECTED`；声音只提供估计区域，绝不授权盲射 |
| 转角交战与不可达目标 | 已有三点搜索、左右候选、完整导航路线与挡枪后的三米换位；到达后必须重新真实看见玩家才开枪 | `SEARCH_CANDIDATE_SKIPPED`、`REPOSITION_REQUESTED`；不扫描 SAIN 的大范围射击点网格 |
| 战术手雷 | 仅向 1.5～6 秒前亲眼看见的 12～35 米同层旧点尝试单条原生轨迹，检查 10 米内同组友军 | `GRENADE_THROWN` / `GRENADE_REJECTED`；每 Bot 20 秒冷却，全局轨迹至多 1 次/秒 |
| 小队帮助、掩护和推进 | 沿用玩家直接命中时 20 米同组单跳告警，只选一名队友推进；其他成员据本人真实视觉还击 | `SQUAD_ADVANCE_SELECTED`；不向队友共享精确隐藏位置 |
| 闪避手雷、近战、原生恢复与武器动画 | 保留游戏原生更高优先级行为，BigBrain 抢占时停止本模组动作并恢复 ADS、武器模式和姿态 | `CONTROL_RELEASED`、`AIM_MODE_RESTORED`、`FIRE_MODE_RESTORED` |

SAIN 中还存在以隐藏敌人实时健康、换弹状态或位置作判断的冲锋分支，多身体部位视觉替换、主动对遮挡目标盲射的压制、持续全图掩体扫描、完整小队战术树、后坐力/射速重写、僵尸专用近战动作。本版没有照搬这些实现：前几项违反玩家专属公平线索或轻量预算，近战/手雷规避和原生武器控制由游戏已有行为处理。因此这是一套覆盖主要玩家交战场景的轻量行为对应，不等同于 SAIN 的全部功能或逐类兼容。若局内日志显示某个场景确有缺口，可针对该场景继续增加独立策略。

## 实测流程

同时替换两个自有 DLL 后重启游戏，确认 `START version=0.3.0`、`COMBAT_TACTICS_RULES` 的五个开关、`READY` 中补丁数量，以及 SAIN/ORBIT 已停用。建议在海岸线同一局按以下场景观察：

1. 10～18 米隔墙走动：Bot 只短暂停看估计脚步点，然后继续搜索；不应穿墙开火。
2. 10～20 米目视后躲进房间：高等级 PMC 有较高概率在守旧出口后靠近；低等级偶尔靠近，Scav 维持固定搜索。记录 `RUSH_SELECTED`、`QUERY_SUCCEEDED`、`MOVE_STARTED`、`MOVE_PROGRESS`，不能只凭状态判断已经移动。
3. Bot 已在掩体处，玩家从视野消失超过 2.5 秒：核对 `COVER_SHIFT_REQUESTED`、`QUERY_SUCCEEDED/FAILED` 和实际到达。受击或重新看到玩家时应中止不合适的换位。
4. 12～35 米被目视后遮挡，并且 Bot 持有手雷：查看 `GRENADE_THROWN` 或 `GRENADE_REJECTED`。友军在旧点十米内、跨楼层、已过六秒或轨迹不合法时都不应投掷。
5. 在五米内和十米外分别暴露：仅真实可见且本层控制时出现 `AIM_MODE_CHANGED`，中间距离保持原状态；层释放后检查 `AIM_MODE_RESTORED`。射击仍需 `SHOT_VALIDATED` 和原生瞄准就绪。

本机编译、接口核对和独立策略测试只验证静态兼容与边界，**尚未完成 0.3.0 游戏内实测**。`GRENADE_THROWN` 表示原生 `DoThrow()` 已接受，并不证明手雷落点正确；`RUSH_SELECTED` 和 `COVER_SHIFT_REQUESTED` 也不证明实际走完路线，应对应移动日志与画面核对。

**性能影响：中，静态分析预估，未实测。** 伏击、突击、ADS 均为玩家情境内的常数时间计算；换掩体复用既有全局碰撞、射线和每帧最多一次完整路径额度。新增原生手雷轨迹检查全局最多每秒一次，并在 `ActionGrenade` 记录同步耗时。若多名 Bot 同时失视且各自申请新掩体或搜索路径，路径队列与主线程 NavMesh 查询会排队；若一次原生手雷轨迹检查耗时较长，它仍可能产生单帧峰值。应结合新战局 `SUMMARY grenadeTrajectories`、`TIMING ActionGrenade`、路径积压和完整游戏帧时间判断。
