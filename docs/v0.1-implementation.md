## 工程组成

- `src/AiBehavior.Core`：面向 `netstandard2.1` 的纯逻辑层，包含角色能力、固定容量观察记忆、并行反应门控、上下文决策、时间令牌与有限轮转队列。
- `src/AiBehavior.Client`：同样面向 `netstandard2.1`，连接本机 EFT/Unity/BepInEx/Harmony/BigBrain。插件 GUID 为 `local.aibehavior.opt`，只发布自有程序集。
- `tests/AiBehavior.Core.Tests`：面向 `net10.0` 的独立断言程序，不通过模拟游戏对象宣称客户端行为已经实测。
- `tools/Build.ps1`：显式调用便携 SDK，核对接口、还原和编译两个工程、执行行为检查，传入 `-Package` 时生成安装包。
- `tools/Verify-GameApi.ps1`：只读 Mono.Cecil 元数据检查。证据输出至被忽略的 `artifacts/verification/game-api.json`，包含版本、游戏程序集 SHA256、签名、角色常量和 `runtimeTested=false`。

## 接入与适配

使用 BigBrain 的四参数 `AddCustomLayer(Type, List<string>, int, List<WildSpawnType>)`，注册一个优先级为 **71** 的自有层，内部切换行为状态。原生层保持注册，空闲、特殊动作或失败时交还控制；每个 Bot 的异常单独降级。

白名单只包含 `pmcBEAR=51`、`pmcUSEC=52`、`assault=1`、`assaultGroup=19`、`marksman=0`；明确排除 `pmcBot=9` Raider。还要核对实际 Brain 为 `PmcBear`、`PmcUsec`、`PMC`、`Assault` 或 `Marksman`。

目标程序集中的补丁与执行入口已按以下精确参数核对：

| 类型和入口 | 参数或用途 |
| --- | --- |
| `EFT.BotOwner.method_10 / Dispose` | 无参，注册完整激活的 Bot / 清理 |
| `EFT.GameWorld.Dispose` | 无参，战局结束清理 |
| `EnemyInfo.CheckLookEnemy` | `LookAllData, float`，在原生个人视觉检查后保存快照 |
| `BotHearingSensor.SoundHeared` | `IPlayer, Vector3, float, bool, AISoundType`，只接管原生判定已听到的敌方声音 |
| `EFT.BotMemory.set_GoalEnemy` | `EnemyInfo`，限制没有有效观察的隐藏目标切换 |
| `BotAimingData.SetTarget / UpdateTarget` | `Vector3`，以最新个人视觉快照限制直接瞄准 |
| `ShootData.Shoot` | 无参、返回 `bool`，新连射受反应和预算内射线验证约束 |
| `BotMover.GoToByWay` | `Vector3[], float`，复用已验证的完整路径 |
| `BotFirstAid.ApplyToSelf` | `int?, Action`，通过原生接口执行急救 |
| `EFT.BotOwner.OnGetHit` | `DamageInfo, EBodyPart, float`，只接收真人枪弹伤害 |
| `EFT.Ballistics.Shot.Update` | `float`，复制原生完成碰撞裁剪后的真人弹道段 |
| `EFT.IPlayer.get_IsAI / get_IsYourPlayer` | 只读身份属性，区分本机真人、AI 和未知来源 |
| `BotLay.set_IsLay / EFT.MovementContext.get_CanProne` | 原生姿态合法性与卧姿控制，不使用会触发全组卧倒的接口 |
| `LookData.ResetUpdateTime` | 唤醒原生视觉扫描，不直接赋予可见性 |

上述十八项方法加 BigBrain 注册入口，共十九项 API 签名；另检查六个角色枚举值。元数据匹配与编译通过不等价于 Harmony 实际安装、执行顺序或 Unity 运行时验证。

## 设计的具体落点

1. 采用单个 BigBrain 层和缓存状态，减少每个 Bot 的组件与独立更新回调。高层决策轮转，单体安全检查逐帧执行。
2. 每个 Bot 最多四条值类型观察。视觉位置与瞄准点一起冻结，只由真实个人视觉回调刷新；声音按声源合并且不在读取时延长寿命。
3. 掩体采用局部候选，不调用原生全量掩体搜索。半径 12 米、32 个碰撞体、六个候选、最多两次候选验证；复用当前原生掩体点只是候选来源，仍需重新验证。
4. 所有自有显式射线、NavMesh 采样、路径计算、局部扫描分别使用全局时间令牌与单帧上限。路径必须完整且满足长度边界，直接交给原生路径执行器。
5. 新连射使用独立轮转验证队列，与普通查询共享物理额度及总队列上限，避免固定 Bot 回调顺序长期垄断射线。许可短期有效且重新核对身份与位移；本版并不计算复杂弹道或队友未来轨迹。
6. 恢复与行动执行复用原生功能，保留原生瞄准散布和射击节奏。等级曲线只约束新增能力门槛，不承诺实际命中率、首发延迟或胜率线性变化。
7. 小队报告延迟仅有曲线定义与检查；0.1.2 的受击告警使用固定限频，只通知同组二十米近邻一次，不转发、不共享精确坐标。完整小队战术、搜刮/任务/撤离、复杂投掷物策略与 Fika 未实现。
8. 不新增专用后台线程，Unity 和游戏对象都在主线程使用。缓存和候选有界；原生返回路径角点会产生有界分配，不宣称零 GC。

所有自有方法带中文说明，复杂决策、查询和生命周期代码附逐行中文注释。参考源码用于核对，本插件不打包游戏 DLL 或参考仓库内容。

## 自动检查

行为检查覆盖三十九组场景、58,266 条断言（其中包含五万次重复停用检查）：

- PMC 全部 1～60 级六项曲线、端点钳制、非法区间，以及固定角色模板。
- 观察容量、到期、声源合并、过期事件、无效坐标和瞄准快照。
- 反应与武器稳定并行、丢失视线、换目标与武器失去就绪后的重置。
- 30/60/144 FPS 下时间额度、单帧上限、暂停后的额度限制、原子双射线预留与时钟回退。
- 队列去重、生命周期代次、截止时间、容量、轮转与取消，以及无效请求。
- 恢复锁、信息过期、状态保持、稳定战术抽样和确定性随机数。
- 停用、重复释放、重新激活及原生层射击任务的清理责任。
- 软预算持续耗尽时的决策公平轮转、跳过停用项、空列表和删除游标补偿。
- 调查范围边界、线索到期、及时交还状态及保留原生恢复。
- 普通日志额度耗尽时的未知脑型首次证据、固定容量和溢出提示。
- 嵌套阶段独占计时、晚于 LateUpdate 的动作、最后一帧去重、峰值组成与极端重入。
- 本机真人身份、AI 互战交接、玩家死亡退出、枪声距离边界与等级定位误差。
- 危险五秒边界、真实危险刷新、普通枪声不续期、低血量/缺弹/恢复中不前压、狙击模板不追击。
- 十二米路径分段与调查寿命、碰撞裁剪后近弹几何、固定弹道容量/超时/游标补偿、几何和友方传播预算。
- 连续危险与重复路径的姿态去重、普通意图稳定窗口、原生恢复/卧姿衔接、控制交接归属、掩体到达边界和非法输入。

完整客户端和检查工程以 Release 构建，启用警告视为错误。以上是独立逻辑和静态接口证据，没有覆盖游戏物理、真实武器/医疗执行、动态导航、Harmony 运行时和其他模组交互。

## 性能判断与后续验收

0.1.2 海岸线采样记录的插件插桩工作平均 0.055 毫秒、峰值 76.223 毫秒；最差帧中动作阶段占 76.206 毫秒，不能据此把峰值归因于显式导航查询。采样还记录了多次导航采样失败和路径不完整，详见 [实测记录](playtests/2026-09-23-shoreline-0.1.2.md)。这些数据不是整帧或全游戏 AI 耗时，且受当局活动 Bot 数等条件影响，不能作为 0.1.3 的性能测量结果。是否实际比 SAIN 更轻需要同场景对照。

主要风险是集中接敌挤满射击队列、掩体失败导致冷却后集中重试、复杂区域单次同步路径计算较慢、逐帧安全检查随受管 Bot 数增长。软预算只阻止继续启动可推迟工作，不能中断 Unity 调用；关键安全处理仍可能超时。

0.1.3 姿态修复的新增开销评为 **低（静态分析，未局内实测）**：每个 Bot 使用固定大小缓存和常数次比较，减少重复姿态写入，不增加物理、导航或弹道查询。多个 Bot 同时变更姿态叠加同步日志阻塞仍可能产生峰值。已有导航失败和动作慢调用并未因这次修复而解决。

后续使用 0.1.3 先复测持续交火、掩体边界移动、卧姿恢复和控制交接，结合 `POSE_CHANGED`、`POSE_RESTORED` 验证蹲站指令是否稳定；继续保留 `PLAYER_SCOPE`、`TIMING` 和查询失败证据，跟进靠近玩家时的寻路问题。玩家枪声/命中/近弹、AI 互战旁路、停用再激活及连续两局也需回归。原生/本插件/SAIN 三组帧时间、GC、查询次数与行为完成率尚未完成对照测量，设计中的比较性能目标不作为已兑现指标。
