# 0.2.2 趴伏边界与近距交战记忆

本版针对“正在对枪时 Bot 趴下”和“同楼层刚交战后玩家躲进房间，Bot 很快放弃索敌”做出修复。2026-09-25 的现有日志记录了数次视觉丢失后约 7～8 秒出现 `MEMORY_EXPIRED`，但 `DangerProne=0`，不能单凭该日志认定玩家看到的趴伏由本模组触发；原生 AI 也可能改变姿态。

- 本模组主动趴伏现在需要同时满足：**本人确实被本机玩家子弹命中、周围掩体候选已验证不可用、没有正在排队的掩体查询或移动、当前看不到玩家**。近弹、队友被命中、仍在对枪或仅因暂未取得掩体结果，不再触发本模组主动趴伏。原生合法性和贴脸八米限制仍保留。Bot 被本模组接管后新增的卧姿，若在可见交火时仍存在，就在下一次动作执行前撤销；接管前原本已有的原生卧姿不被改写。
- 玩家仍可见但掩体查询失败时，Bot 不会为了趴伏先停止战斗；受限自卫仍需短暂受惊结束、压力未达最高档、武器与原生瞄准就绪及枪线检查。本人失视且无可用掩体时仍可尝试已有的有限短距撤离。
- 持续目视的近距交战中，最后亲眼看见的位置与 Bot 高差不超过 2.5 米、水平距离不超过 35 米时，Scav 保留 18 秒、狙击 Scav 保留 20 秒、PMC 按等级保留 23～27 秒。首次短暂目击、远距和明显跨层仍沿用原来的角色记忆基线。这里的“同层”只依据上次真实视觉快照的高度差推断，不读取失视后玩家的当前位置，也不授予隔墙射击能力。
- 新的脚步声仍可更新估计搜索区域，但不会把此前同一目标更长的有效视觉记忆缩短到脚步线索自身的八秒上限。没有新证据时，读取记忆不会续期。三点候选都查完后，近距同层交战的 Bot 会守住最后线索区域直到记忆到期或重新发现玩家；不新增第四个寻路候选，路径预算和射击安全边界保持原样。

## 局内复测

同时替换两个自有 DLL，重启游戏确认 `START version=0.2.2` 与 `COMBAT_MEMORY_RULES`。建议在同一楼层同一房间口分别测试：正面交火但没有命中 Bot、打偏形成近弹、真正命中后仍保持互相可见、命中后玩家躲入房间且附近掩体查询失败。只有最后一类场景可能出现 `DANGER_PRONE reason=personal-hit-no-cover-no-visual`。`DANGER_PRONE_SKIPPED reason=visible-target` 或 `no-personal-hit` 可证明本模组拒绝了不合条件的趴伏；`VISIBLE_PRONE_CLEARED source=external` 表示本层接管后有其他行为设成卧姿，现已在可见交火时撤销。没有这些日志时，不能仅凭画面推断姿态由谁发起。

观察 `SIGHT_CHANGED visible=False memoryLeft=...`、随后的 `SEARCH_AREA_HELD` / `STATE_CHANGED` / `SEARCH_FINISHED` / `MEMORY_EXPIRED`。失视后 Bot 只能围绕最后合法线索寻找，不能隔墙精确瞄准；如果仍然很快放弃，应结合同一个 Bot 编号查看线索是否为首次短暂目击、跨层、路径不可达或被其他原生行为层抢占。

**性能影响：低，静态分析预估，尚未做 0.2.2 局内测量。** 趴伏条件与记忆时长只增加固定标量和几次平方距离比较；没有新射线、NavMesh 查询、Bot 全局扫描或无限容量状态。较长的同层搜索会使单个 Bot 在原有预算内维持搜索更久；若许多 Bot 同时在近距同层失视并持续申请路径，既有全局路径额度和原生寻路仍可能成为瓶颈，需要用新局内 `TIMING` 和 `COUNTERS` 核对。
