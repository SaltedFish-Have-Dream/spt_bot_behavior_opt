# AI Behavior Opt 0.1.0 使用说明

这是首版开发验证包。已完成本机构建、行为核心检查和目标程序集接口核对；尚未验证游戏内行为、Harmony 实际挂接或相对 SAIN 的性能收益。建议先用单独测试配置进入练习战局。

## 安装与停用

目标版本：SPT **4.1.5**、EFT **0.16.9.5-40743**、BigBrain **1.5.0**。插件检查这些版本，其他版本需要重新适配和验证。

1. 关闭游戏；在测试安装中停用 **SAIN、ORBIT**，保留 BigBrain 1.5.0。将冲突 DLL 及其专属目录移出 `BepInEx/plugins`；只在该目录内部重命名文件夹不能可靠停用插件。
2. 将发布包中的 `BepInEx` 目录合并到游戏根目录。安装后应有 `BepInEx/plugins/AiBehaviorOpt/AiBehavior.Client.dll` 和 `AiBehavior.Core.dll`。
3. 启动游戏，检查 `BepInEx/LogOutput.log` 中的版本、冲突和初始化消息。配置文件为 `BepInEx/config/local.aibehavior.opt.cfg`。
4. 进入少量 Bot 的测试战局，确认实际能移动、交战、换弹和退出战局，再逐步增加场景复杂度。

停用时将 `General.Enabled` 改为 `false` 并重启，或关闭游戏后移出本插件目录。此版本不修改服务端数据库或存档。构建脚本不会自动安装或停用其他模组。

## 角色与等级

| 角色 | 首版行为 |
| --- | --- |
| PMC：`pmcBEAR`、`pmcUSEC` | 共用行为库，能力参数按等级线性变化 |
| 普通 Scav：`assault`、`assaultGroup` | 固定能力模板，不随等级变化 |
| 狙击 Scav：`marksman` | 固定狙击模板，不执行本插件的搜索移动和掩体移动 |
| Boss、护卫、Raider：`pmcBot`、其他角色 | 不注册本插件上下文，保留原生行为 |

只有角色白名单和实际 Brain 名称同时匹配才会接管。出现未知 Brain 会记录提示并保留原生行为。

| PMC 参数 | 1 级 | 60 级 |
| --- | --- | --- |
| 察觉反应最低时间 | 0.90 秒 | 0.30 秒 |
| 武器就绪后稳定最低时间 | 0.80 秒 | 0.35 秒 |
| 听觉基础定位误差 | 8 米 | 3 米 |
| 视觉记忆寿命 | 6 秒 | 14 秒 |
| 战术动作倾向 | 0.30 | 0.85 |

中间等级逐项线性插值，超出区间按端点钳制。反应和稳定计时并行推进，还必须满足原生武器、瞄准、射击节奏和本插件射线验证；表中时间不是实际首发延迟保证。高等级不会得到更多寻路或射线额度。小队报告延迟曲线仅预留数据，本版没有小队广播功能。

## 信息与行为边界

视觉只在原生个人视觉检查完成后保存位置和瞄准点快照；直接瞄准还要求对应最新个人可见记录且不超过 0.35 秒。两次观察之间不继续读取隐藏敌人的身体坐标。丢失直接视线后停止持续射击；进入搜索时只使用记忆快照。

听觉沿用原生是否听到的判定，对实际听到的敌方声音记录一次带误差位置；误差按距离修正，同一声源一秒内合并。每个 Bot 最多保留四条观察，声音最多保留八秒。受管 Bot 的这一听觉分支由本插件接管，不继续执行原生该分支的群组通知；本版未实现替代小队通信。

调查和搜索最多选择三个点，调查中心距开始位置限制为 Scav 25 米、PMC 60 米，完整路径长度限制为 35/80 米。目标过期、搜索完成或连续失败后放弃该意图。无有效线索时交回原生层；首版不重写完整巡逻路线。

掩体使用半径 12 米的局部碰撞体扫描和可用的原生当前掩体点。扫描缓冲最多 32 个碰撞体，保留最多六个候选，每次请求最多验证两个候选；候选必须通过导航投影、遮挡和完整路径检查。缓存最长八秒，已知威胁移动超过五米时失效。该策略不保证复杂房间、动态门或可破坏物体下总能找到有效掩体。

恢复复用原生换弹和急救，尝试间隔至少两秒。低血量脱离优先使用已验证掩体，不包含完整撤离路径。手雷规避、故障处理等更高优先级原生层保留；投掷过程不申请本插件控制权。

## 默认配置与预算

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `General.Enabled` | `true` | 总开关 |
| `General.ManageScavs` | `true` | 同时接管普通与狙击 Scav |
| `PMC.MinimumLevel / MaximumLevel` | `1 / 60` | 线性成长区间；非法组合回退默认区间 |
| `Performance.DecisionBudgetMs` | `0.5` | 新增主线程工作的每帧软时间片，毫秒 |
| `Performance.RaysPerSecond` | `120` | 射线令牌每秒补充量，单帧最多八个 |
| `Performance.PathsPerSecond` | `12` | 显式寻路每秒补充量，单帧最多一次 |
| `Performance.SamplesPerSecond` | `36` | 导航位置采样每秒补充量，单帧最多三次 |
| `Performance.OverlapsPerSecond` | `6` | 局部碰撞体扫描每秒补充量，单帧最多一次 |
| `Diagnostics.SummarySeconds` | `30` | 汇总日志间隔；零关闭 |
| `Diagnostics.TraceBots` | `false` | 注册与能力诊断日志 |

本版配置在启动时读取，修改后重启游戏。能力端点暂在源码中定义，未开放所有参数热修改。

战斗、警戒、空闲高层决策分别按最高 5/2/0.5 Hz 调度，安全检查和受管动作仍逐帧处理。普通决策最多使用软时间片的 40%，为动作和查询留出时间。查询合计容量不超过 `min(4 × 受管 Bot 数, 256)`，射击单独轮转并优先处理，普通请求一秒超时，射击请求 0.2 秒超时。

每次新连射验证原子预留两个射线令牌，检查实体遮挡与枪线上的其他玩家。通过后的许可最多保留 0.1 秒，还要复核目标身份、枪口移动不超过 0.25 米、瞄准点移动不超过 0.5 米，消费一次即失效。多人同时交战会增加排队，低配额可能明显推迟开火；不能把射击停滞当作性能优化收益。

软预算不能中断已经开始的同步 NavMesh/物理调用，逐帧安全检查和至少一次关键队列处理也可能使其超时。原生视觉、运动、动画和其他插件的全部调用不受本插件额度约束，故 0.5 毫秒不是整局 AI 耗时或最坏帧保证。

路径无进展超过 2.5 秒会停止当前移动，连续失败两次进入五秒冷却并放弃当前候选；第一次失败使用 0.8 秒重试间隔。完整路径复用避免显式重复寻路，但路径角点数组仍可能分配内存，不承诺零 GC。

## 日志与游戏内验收

日志中的 `AI汇总` 包含受管数量、累计平均/峰值工作耗时、超软预算帧、查询完成/失败、队列过期、射击等待峰值和状态切换。`rayTokens` 是预留额度，`rayCalls` 是实际调用次数，两者可能不同。计时覆盖本插件已插桩入口，不代表全游戏 AI 开销或完整帧时间。

按以下顺序进行首次验收：

1. 少量 PMC/Scav 完成出生、巡逻衔接、接敌、击杀、死亡和连续两次进出战局，检查异常日志与旧对象残留。
2. 遮挡和转角丢失视线后停止直接射击；声音误差、记忆到期和三点搜索可观察；友军挡枪时不开始新连射。
3. 观察门口、楼梯、窄掩体和不可达位置的移动回退；检查换弹、急救、手雷规避、故障处理和原生层抢占后的动作恢复。
4. 同装备用 PMC 1/20/40/60 级比较多轮行为；确认 Scav 模板不随等级变化、Boss/护卫/Raider 未被接管。远距离待机与再次激活也需要单独测试。
5. 固定地图、出生与负载，对比原生、仅本插件、仅 SAIN 三组。可从 10/30/60 Bot 测试点收集帧时间、峰值、GC、查询次数和行为完成率；这些是测试点，不是已验证的支持容量。

当前性能影响档次为 **低（静态分析预估，未实测）**：新增查询有界、限频且有缓存。大量 Bot 同时重新接敌或寻找掩体、复杂区域较长的同步寻路、移动目标使射击许可反复失效时，可能出现中、高档瞬时开销或行为响应延迟。相对 SAIN 的收益需上述同场景对照确认。

本版没有服务端改动、完整搜刮/任务/撤离、复杂侧翼与投掷物战术、小队协作、Boss 专属改造或 Fika 联机适配。游戏内尚未测试，因此也不宣称与其他 AI 模组普遍兼容。
