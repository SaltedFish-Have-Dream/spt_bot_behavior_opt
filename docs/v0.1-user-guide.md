# AI Behavior Opt 0.1.7 使用说明

这是玩家专属拟真行为的开发验证包。0.1.7 增加失视后短暂守住最后目击位置，以及同区域再次探头时更快重新准备交战；沿用 0.1.6 的有限撤离、挡枪换位和搜索失败记忆。参考 SAIN 的设计思路，自主实现轻量逻辑，不依赖 SAIN。实际地形、动画、控制交接和性能峰值尚待新版局内实测；详见包内 `repeek-awareness.md`。

## 安装与停用

目标版本：SPT **4.1.5**、EFT **0.16.9.5-40743**、BigBrain **1.5.0**、SPT-Waypoints **1.9.0**。插件检查这些版本，其他版本需要重新适配和验证。

1. 关闭游戏；在测试安装中停用 **SAIN、ORBIT**，保留 BigBrain 1.5.0 和 SPT-Waypoints 1.9.0。将冲突 DLL 及其专属目录移出 `BepInEx/plugins`；只在该目录内部重命名文件夹不能可靠停用插件。
2. 将发布包中的 `BepInEx` 目录合并到游戏根目录。安装后应有 `BepInEx/plugins/AiBehaviorOpt/AiBehavior.Client.dll` 和 `AiBehavior.Core.dll`。
3. 启动游戏，确认 `BepInEx/LogOutput.log` 中有 `event=START version=0.1.7`、`VISION_RULES`、`NAVIGATION_RULES dependency=Waypoints version=1.9.0`、`PLAYER_RULES mode=local-human-only` 和 `TACTICAL_RULES`。基础 `READY patchedMethods=11 expectedMethods=11`；AI Limit 1.9.2 适配成功时为 `12/12`。升级时两个自有 DLL 必须同时替换；沿用原配置即可，配置文件为 `BepInEx/config/local.aibehavior.opt.cfg`。
4. 进入少量 Bot 的测试战局，确认实际能移动、交战、换弹和退出战局，再逐步增加场景复杂度。

停用时将 `General.Enabled` 改为 `false` 并重启，或关闭游戏后移出本插件目录。此版本不修改服务端数据库或存档。构建脚本不会自动安装或停用其他模组。

## 角色与等级

| 角色 | 首版行为 |
| --- | --- |
| PMC：`pmcBEAR`、`pmcUSEC` | 共用行为库，能力参数按等级线性变化 |
| 普通 Scav：`assault`、`assaultGroup` | 固定能力模板，不随等级变化 |
| 狙击 Scav：`marksman` | 固定狙击模板，不执行本插件的搜索移动和掩体移动 |
| Boss、护卫、Raider：`pmcBot`、其他角色 | 不注册本插件上下文，保留原生行为 |

只有角色白名单和实际 Brain 名称同时匹配才会接管。出现未知 Brain 会记录提示并保留原生行为。

| PMC 参数 | 1 级 | 60 级 |
| --- | --- | --- |
| 察觉反应最低时间 | 0.90 秒 | 0.30 秒 |
| 武器就绪后稳定最低时间 | 0.80 秒 | 0.35 秒 |
| 听觉基础定位误差 | 8 米 | 3 米 |
| 视觉记忆寿命 | 6 秒 | 14 秒 |
| 战术动作倾向 | 0.30 | 0.85 |

中间等级逐项线性插值，超出区间按端点钳制。反应和稳定计时并行推进，还必须满足原生武器、瞄准、射击节奏和本插件射线验证；表中时间不是实际首发延迟保证。高等级不会得到更多寻路或射线额度。听到 30 米以内玩家枪声后，两秒内豁免上述新增等级等待，仍需原生瞄准就绪和真实视线。小队报告延迟曲线仅预留数据；本版的受击告警采用固定限频，不使用这条等级曲线。

## 信息与行为边界

所有新增感知、记忆、等级门控、决策、搜索、掩体和射击验证只针对 `IsAI=false` 且 `IsYourPlayer=true` 的本机真人。AI 与未知来源走原生入口，不因 AI 互射新增危险记录、查询或日志明细。玩家视觉、脚步仍可激活已有增强，并非只响应开枪。目标切换成其他 AI 时撤销旧玩家查询、归还控制；玩家新造成的五秒危险可临时优先避险。未与玩家发生交互的受管 Bot 仍保留轻量来源/生命周期检查，并非完全零开销。

视觉只在原生个人视觉检查完成后保存位置和瞄准点快照；直接瞄准还要求对应最新个人可见记录且不超过 0.35 秒。两次观察之间不继续读取隐藏敌人的身体坐标。丢失直接视线后停止持续射击；进入搜索时只使用记忆快照。

听觉沿用原生是否听到的判定，仅接管真人脚步和枪声。脚步每秒最多生成一次快照、最多保留八秒；枪声独立每 0.25 秒合并一次，保留 12～45 秒，不因读取续期。每个 Bot 最多四条观察。新鲜直接视觉优先于声音，不广播玩家精确坐标。

枪声 0～30 米（含 30）记住开枪时的位置并快速警戒；超过 30 至 120 米（含 120）带误差定位和搜索；超过 120 米的未命中、无近弹枪声不触发增强。误差为角色基础听觉误差乘以距离系数：30 米外从 0.5 倍连续增至 120 米的 2 倍。PMC 随等级提高更准确，普通 Scav 和狙击 Scav 固定；不会隔墙授予视线或持续追踪隐藏玩家。

任意距离的玩家枪弹命中、2.5 米内的实际近弹/弹着触发 `Evade`：取得控制后降低姿态，优先前往附近已验证掩体；有限候选确实失败后尝试原生合法趴伏。距估计威胁不足八米、身体/地形不允许、或正在治疗/换弹时不强制趴伏。若掩体已确认不可用、卧姿又因贴脸或原生限制无法执行，普通 Scav 与 PMC 最多尝试两次完整路径约五米的短距撤离；已经卧姿的 Bot 不会被本逻辑强制站起。预算等待不等于没有掩体，不能保证在开枪同一帧完成寻路。普通枪声不刷新避险；距最后一次真实危险五秒后，生命与弹药允许时进入 `Advance`，向最后合法快照有限推进，先完成已有治疗/换弹。低血量或缺弹不会强制冲锋。

直接命中还会通知受害者 20 米内同组的活动受管成员，接收者不再转播；采用全局每秒补充四次、突发容量一次的额度，避免霰弹重复扩散。直接受害者的命中处理不限该额度。这里的友方指同一 `BotsGroup`，不扩大到所有同阵营 Bot；Boss、护卫、Raider 自身仍为原生逻辑。

调查和搜索最多选择三个点，先求完整可达路线，再沿真实折线每次推进最多 12 米；路线最多 128 个角点，缓存八秒，调查绕行上限为 `max(80, min(360, 目标直线距离 × 3 + 20))` 米。每次请求最多四次有限候选验证，不等于扩大听觉范围。普通脚步/视觉丢失搜索仍限制中心为 Scav 25 米、PMC 60 米；有效枪声和危险调查使用独立寿命，不因短视觉覆盖提前退回这两个半径。狙击 Scav 不离岗追击。实际到达需检查原生剩余路径距离，失败退出与搜索完成分开记录。

同一搜索点连续两次因导航投影、路径不完整或绕行超限失败时，十五秒内跳过其五米邻域，最多缓存三个点；其他位置仍可调查。真实看见玩家但连续三次被世界障碍挡枪时，持有本插件控制的普通 Scav 与 PMC 最多尝试左右各一次三米侧移，仍受完整路径、视线与友军射击保护约束。Waypoints 改善地图导航基础，不保证本插件每条候选路线都可达。

掩体使用半径 12 米的局部碰撞体扫描和可用的原生当前掩体点。扫描缓冲最多 32 个碰撞体，保留最多六个候选，每次请求最多验证两个候选；候选必须通过导航投影、遮挡和完整路径检查。缓存最长八秒，已知威胁移动超过五米时失效。该策略不保证复杂房间、动态门或可破坏物体下总能找到有效掩体。

恢复复用原生换弹和急救，尝试间隔至少两秒。低血量脱离优先使用已验证掩体，不包含完整撤离路径。手雷规避、故障处理等更高优先级原生层保留；投掷过程不申请本插件控制权。

0.1.3 普通姿态改为统一提交：危险期间移动和停留使用相同低姿态，重复路径不强制起身；普通姿态意图需持续稳定 0.75 秒，新的危险压低仍立即执行。掩体到达采用 1.2 米进入、1.8 米离开的距离缓冲，减少边界抖动。交还控制只恢复仍由自己持有的姿态。详细复测说明见包内 `posture-fix.md` 或源码 `docs/v0.1.3-posture-fix.md`。

0.1.4 对同一区域连射复用一次定位误差，避免反复取消路线；BigBrain 再次选中同一个动作时可恢复一次控制，原生高优先级层不被强夺。AI Limit 1.9.2 仅优先一百二十米内已有玩家情境的对象，保留它的活动数量上限和检查周期，不保证所有附近 Bot 同时活动；未收到事件的停用对象不会凭空得到声音线索。

0.1.5 在 Bot 到达自有掩体后被玩家直接命中时，将该点两米内的位置排除十二秒，每个 Bot 最多保存四项；近弹和同组告警不构成掩体失效证据。个人命中与近弹形成有上限、会衰减的压力，高压优先隐蔽；压力回落、距最后危险至少 0.75 秒且已在有效掩体有真实视线时，才尝试原生验证后的还击，不提供盲射或自动探头。危险的五秒规则不延长。

沿有效搜索路线接近线索、剩余路线在 1.2～18 米之间时，可以短暂停看。默认 PMC 1 级约 0.70 秒、60 级约 0.50 秒，中间线性变化；Scav 使用固定模板。同一区域最多两次，间隔至少六秒且需前进六米，不延长线索或路线寿命，遇危险或控制交接取消。有效掩体移动也会保持到达承诺，普通视线变化不会让它随意停在半路，已开始的医疗、原生高优先级层和失效路线仍可打断。详见包内 `tactical-response.md`。

0.1.7 在真正失去玩家视线后短暂看守最后亲眼目击的位置，最多 1.25 秒，然后恢复已有调查；不会对隐藏位置直接瞄准或开火。八秒内在该位置六米范围重新**真正看见**同一玩家，本次连续可见的等级反应和准备等待缩至八成，但仍要满足原生武器、瞄准、视线及枪线条件。新危险、换弹治疗与掩体移动仍优先，详细边界见包内 `repeek-awareness.md`。

| `Tactics.CoverFailureMemory` | `true` | 在已到达掩体处遭玩家命中后，短期排除该点 |
| `Tactics.SuppressionResponse` | `true` | 个人压力衰减、高压隐蔽与掩体内条件还击 |

| `Performance.DecisionBudgetMs` | `0.5` | 新增主线程工作的每帧软时间片，毫秒 |
| `Performance.RaysPerSecond` | `120` | 射线令牌每秒补充量，单帧最多八个 |
| `Performance.PathsPerSecond` | `12` | 显式寻路每秒补充量，单帧最多一次 |
| `Performance.SamplesPerSecond` | `36` | 导航位置采样每秒补充量，单帧最多三次 |
| `Performance.OverlapsPerSecond` | `6` | 局部碰撞体扫描每秒补充量，单帧最多一次 |
| `Diagnostics.SummarySeconds` | `30` | 汇总日志间隔；零关闭 |
| `Diagnostics.TraceBots` | `false` | 注册与能力诊断日志 |
| `Diagnostics.EventLogging` | `true` | 限频关键事件明细；关闭后保留计数和最终汇总 |
| `Diagnostics.EventLogsPerSecond` | `8` | 全部 Bot 共享的明细令牌每秒补充量与突发上限 |

本版配置在启动时读取，修改后重启游戏。能力端点暂在源码中定义，未开放所有参数热修改。

只有玩家情境中的 Bot 运行新增高层决策，通常间隔为可见战斗 0.2 秒、有线索 0.5 秒、其余 2 秒，感知变化可提前唤醒。安全检查和受管动作仍逐帧处理；稳定停用期只检查活动状态。普通决策以软时间片的 40% 为阈值，每帧至少保障一个到期项，后续遵守阈值；不承诺固定响应延迟。紧急查询、射击、普通查询依次轮转，共享物理额度及 `min(4 × 受管 Bot 数, 256)` 容量；超时分别为 2.5/0.2/1 秒。

近弹复用原生完成碰撞检测后的轨迹终点，不为 AI 子弹建队列、不额外做近弹物理射线。玩家弹道队列固定 64 段、有效期 0.2 秒；几何筛选每秒补充 6,000 次，单帧最多 256 次。超过容量或超时会丢弃近弹段并记录 `bulletDropped/bulletExpired`，不延后积压成无限计算；直接命中走独立入口。

每次新连射验证原子预留两个射线令牌，检查实体遮挡与枪线上的其他玩家。通过后的许可最多保留 0.1 秒，还要复核目标身份、枪口移动不超过 0.25 米、瞄准点移动不超过 0.5 米，消费一次即失效。多人同时交战会增加排队，低配额可能明显推迟开火；不能把射击停滞当作性能优化收益。

软预算不能中断已经开始的同步 NavMesh/物理调用，逐帧安全检查、一次到期决策保障和至少一次关键射击队列处理也可能使其超时。原生视觉、运动、动画和其他插件的全部调用不受本插件额度约束，故 0.5 毫秒不是整局 AI 耗时或最坏帧保证。

路径无进展超过 2.5 秒会停止移动并废弃缓存；调查路线连续失败两次进入五秒冷却并放弃当前候选，第一次失败使用 0.8 秒间隔。三个候选检查结束后，若仍有失败且线索剩余至少八秒，只允许一次额外重试轮，等待三秒且跳过已到达点。搜索请求最多等待四秒，全局预算不变。路径角点及实际提交段仍会分配数组，不承诺零 GC。

## 日志与游戏内验收

日志统一以 `[ABO]` 标识，正常使用默认配置就会记录关键事件。`run` 区分游戏进程，`raid` 区分该进程内连续战局，`bot` 是本插件生成的匿名序号，`t` 为 Unity 局内时钟。`START` 中的 `build` 是 DLL 标识，可检查是否装入新版本。具体判读和归档步骤见 [实测日志说明](playtest-logging.md)。

日志中的 `AI汇总` 增加 `active/inactive`、决策平均/最大等待与当前积压；`TIMING` 给出十五个阶段（含七个新增动作子阶段）的独占累计耗时、调用次数、单次峰值和最差帧组成。`rayTokens` 是预留额度，`rayCalls` 是实际调用次数。计时覆盖已插桩的插件入口与其中同步原生调用，包含周期汇总，排除初始化前菜单、最终汇总和清场；仍不是全游戏 AI 耗时或完整帧时间。上一帧在下一帧入口结算，晚于 LateUpdate 的回调不再漏计。周期汇总自身会计入后续汇总。

`COUNTERS` 保存本局累计事件与拒绝原因。普通明细共享日志令牌，同一个 Bot 同类事件至少间隔两秒；被合并的次数记录在 `suppressed`。生命周期边界、最终汇总、异常及每局首次未知角色/脑型组合不受普通明细开关与令牌影响；未知组合最多保留 32 种，再输出一次容量提示。`SummarySeconds=0` 仅关闭周期汇总，退出仍有最终汇总和 `RAID_END`。`TraceBots` 通常保持关闭即可。

实测后先保留本次 `BepInEx/LogOutput.log`，避免重启游戏覆盖日志。在项目目录运行 `& '.\tools\Collect-Logs.ps1'` 可归档完整日志、相关配置和已安装的自有 DLL 校验值到 `artifacts/playtests`；也可以实测结束后直接告知助手读取并分析。

按以下顺序进行首次验收：

1. 少量 PMC/Scav 完成出生、巡逻衔接、接敌、击杀、死亡和连续两次进出战局，检查异常日志与旧对象残留。
2. 遮挡和转角丢失视线后停止直接射击；声音误差、记忆到期和三点搜索可观察；友军挡枪时不开始新连射。
3. 观察门口、楼梯、窄掩体和不可达位置的移动回退；检查换弹、急救、手雷规避、故障处理和原生层抢占后的动作恢复。
4. 同装备用 PMC 1/20/40/60 级比较多轮行为；确认 Scav 模板不随等级变化、Boss/护卫/Raider 未被接管。远距离待机与再次激活也需要单独测试。
5. 固定地图、出生与负载，对比原生、仅本插件、仅 SAIN 三组。可从 10/30/60 Bot 测试点收集帧时间、峰值、GC、查询次数和行为完成率；这些是测试点，不是已验证的支持容量。

0.1.5 新增开销评为 **低（静态分析，未局内实测）**：失效点记忆固定四项，压力只更新标量，搜索停看复用路线和动作入口，不增加独立物理扫描；查询预算及日志限频不变。多个 Bot 同时换掩体、压力回落后排队还击会竞争额度；导航的一次同步慢调用、原生动作和日志监听器阻塞仍可能形成瓶颈。独立 .NET 10 热循环检查没有观察到新增纯逻辑的托管分配，不代表游戏 Mono、客户端路径数组和日志整体零 GC。旧版峰值是否消除仍需查看局内计时。
