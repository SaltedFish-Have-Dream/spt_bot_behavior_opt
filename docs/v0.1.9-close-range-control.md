# 0.1.9 贴脸交战控距

目标环境：SPT 4.1.5、EFT 40743、BigBrain 1.5.0、Waypoints 1.9.0。本版参考本地 SAIN v4.5.1 的 `DogFightDecisionClass` 与 `DogFight`：近战可依据视线和动作阶段后撤、接近或停止移动。这里仅自主实现一次有限后撤，不复制其多候选随机采样、敌人全列表排序或原生战斗动作替换。0.1.9 尚未经过游戏内实测。

## 行为边界

Bot 必须实际取得本插件的 BigBrain 层控制，处于 `Engage`，当前目标为本机真人，原生个人视觉确实看见玩家，且同一目视窗口持续至少 0.5 秒。只有玩家相对 Bot 的水平距离在一米至小于六米、高差不超过 2.5 米时才提出三米反向候选；一米内方向不可靠，不推断后撤。六米及以上继续沿用 0.1.8 的一次主动侧移。两种动作共用每次连续交战的一次申请名额，成功排队的挡枪换位也占用该名额。

已有已验证掩体、玩家枪弹危险、治疗/换弹、已有路径或查询、射击验证未结束、狙击 Scav、原生卧姿、手持近战武器或层控制失效时均不申请。候选只由最新个人视觉位置和 Bot 当前位置计算；不读取失视玩家实时坐标，不扫描其他敌人。真正后撤要通过原有导航源点、投影、完整路径、终点和最长十二米绕行检查，仍复用每帧最多一次完整路径计算的全局额度。排队失败保留本窗口机会并受原有半秒重试限制；成功排队后，即使导航失败也不在本窗口无限更换方向。后撤中瞄准与开火继续走原生准备及本插件枪线验证。玩家危险、恢复、视线丢失、状态切换和原生高优先级层均可中断。

默认 `Tactics.CombatRangeControl=true`。设置为 `false` 并重启，可只关闭贴脸后撤；`Tactics.CombatFootwork` 单独控制六至二十五米侧移。`COMBAT_RULES` 显示实际开关和边界。`CLOSE_RANGE_RETREAT_REQUESTED` 仅证明请求排队；同 Bot 的 `QUERY_SUCCEEDED kind=Reposition`、`MOVE_STARTED`、`MOVE_PROGRESS` 和 `REPOSITION_ARRIVED reason=close-range` 才能依次证明路径通过、提交、发生位移和到达。`QUERY_REJECTED`、`QUERY_FAILED` 或 `STUCK` 则说明未完成后撤。普通明细受全局日志额度与同 Bot 两秒限频约束，`COUNTERS` 保留被限频事件的累计数。

建议在海岸线用一名普通 PMC 或 Scav、无遮蔽的二至五米目视接敌观察首次后撤；随后在六至十米验证仍是侧移。再对照 Bot 已在掩体、换弹、正遭近弹压制、被原生层抢占、玩家绕墙失视和两次连续贴近的情形。重点观察后撤是否让 Bot 倒退撞墙、路径成功但未产生实际位移、后撤后立即挡枪横跳，以及后撤中开火是否异常。上一版日志不能证明 0.1.9 已加载或实际执行。

性能影响：**低，静态分析预估，未实测**。每个玩家目视交战 Bot 只增加常数时间的平方距离与方向计算，借用 0.1.8 的固定窗口状态；后撤与侧移共享一次申请名额，不提高单 Bot 单窗口的路径申请上限。若多个 Bot 同时在一至六米处看见玩家、均无已验证掩体，路径请求会集中竞争全局每帧一次完整路径计算额度，可能排队或到期；同步 NavMesh 调用仍可能产生单帧峰值。没有新增服务端和网络处理。
