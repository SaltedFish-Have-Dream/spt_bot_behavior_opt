# 0.1.6 受阻后的有限导航反馈

目标环境：SPT 4.1.5、EFT 40743、BigBrain 1.5.0、SPT-Waypoints 1.9.0。本版针对 0.1.5 海岸线日志中的原地避险、重复挡枪、反复查询不可达搜索点落地修复。上述发现及证据见 `playtests/2026-09-23-shoreline-0.1.5.md`。此版尚未经过游戏内实测。

## 前置与实现边界

Waypoints 1.9.0 已设为 BepInEx 硬前置；构建前检查本机安装文件，启动时检查实际加载版本。Waypoints 提供地图导航网格、门链接等基础数据；本模组的掩体、搜索、短距撤离和换位仍使用自己的分帧 `NavMesh.CalculatePath` 查询。只接受 `PathComplete`，并核对源点、终点、楼层、高度及路径长度；不能把 Waypoints 对其他接口允许的部分路径直接视为可达。

新动作只响应本机真人相关事件、只由实际取得 BigBrain 控制的受管普通 Scav 或 PMC 执行。狙击 Scav 不离岗；Boss 等未受管角色保持原生行为。原生撤离、手雷规避、故障等更高优先级层不被覆盖。

## 行为变化

1. 受玩家枪弹威胁时仍先找验证过的掩体。只有局部候选已经实际失败，且原生卧姿检查返回贴脸或地形/身体禁止、当前没有掩体或其他移动请求时，才沿已知威胁快照规划最多两处约五米短距撤离点。两次至少间隔三秒；导航不完整、绕行超过十二米或控制权丢失均放弃。已有原生卧姿不主动站起。危险结束后恢复原有安静五秒推进规则。
2. 真人已被真实看见、处于本模组交战/观察动作且世界障碍连续挡住三次枪线时，尝试三米侧移。相同目标每段交战最多左右各一次，至少间隔八秒；换目标重置额度。受击避险、治疗换弹、狙击模板、失去实际控制或视线时不触发。仍保留原有世界障碍与友军射击安全检查，不准向掩体盲射。
3. 搜索候选连续两次导航失败，且实际原因是投影失败、路径不完整或绕行超限时，记住该点十五秒。每个 Bot 最多三个固定槽；五米内新候选直接记为失败并尝试剩余位置，不冒充“已经搜到”。到期后可再次验证动态门或导航变化。卡住和预算截止不会被误当作固定断路。

这三个反馈沿用原有全局导航、采样和射线额度，不新建全场 Bot 扫描，也不读取被遮挡玩家的实时坐标。查询成功仅表示路径可提交；实际到达分别记录 `ESCAPE_ARRIVED` 或 `REPOSITION_ARRIVED`。

## 局内复测

- 启动后确认 `START version=0.1.6`、`NAVIGATION_RULES dependency=Waypoints version=1.9.0` 和 `READY`；缺少前置应由 BepInEx 拒绝加载，不能将旧版日志误当新包结果。
- 在海岸线找无有效掩体且不能趴伏的受击场景，对照 `DANGER_PRONE_SKIPPED`、`ESCAPE_REQUESTED`、`QUERY_SUCCEEDED/FAILED`、`MOVE_STARTED/PROGRESS`、`ESCAPE_ARRIVED`。一次请求或路径成功都不能单独证明 Bot 真正离开枪线。
- 对近处能看见玩家却被石头或墙沿挡枪的 Bot，对照 `ShotWorldBlocked`、`REPOSITION_REQUESTED`、实际移动和随后射击接受。友军在枪线中仍应被拦截。
- 对原来反复出现 `PathPartial` 的搜索区域，观察 `SEARCH_CANDIDATE_SKIPPED` 是否在十五秒内减少同一区域重算，同时确认其他候选仍被调查。
- 检查 `CONTROL_WAITING nativeLayer=Exfiltration`。本版保留原生撤离层优先级；如仍出现长时间等待，需结合局内撤离动作观察后单独设计交接，不能凭查询修复宣称已解决。

性能影响静态预估为低：每个受管 Bot 只保留常数大小状态、三个失败点；主要新增开销是少量短距路径查询，仍受原预算限流。若大量 Bot 同时遭玩家连射且均无掩体、无法趴伏，路径队列可能堆积并接近截止时间；同步原生寻路的单帧耗时仍应结合下一局 `TIMING` 测量。本版未得到新的游戏帧耗时，不能将 0.1.5 的数据当成本版结果。
